# Sort It Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the game "Sort It": the child drags 6 everyday objects into the 2 baskets they belong to (each basket starts with an example card of its group), plus a "Group" field on cards in the admin and in the JSON import.

**Architecture:** Plain React + CSS with Pointer Events written in the repo (no drag library). Pure units hold the logic (`lib/sort/groups.ts`, `rounds.ts`, `drag.ts`); a hook owns the pointer lifecycle; the page orchestrates sounds, timing and the finish. One additive migration adds `memory_cards.category`; the game reads it with its own fetch so Memory Match and Listen & Pick keep their queries.

**Tech Stack:** Next.js 16, React 19, TypeScript, Supabase, Vitest + Testing Library (jsdom), Playwright (real mouse, stand-in Supabase). No Phaser (ADR-030).

**Spec:** `docs/superpowers/specs/2026-10-30-sort-it-design.md`

## Global Constraints
- Round: 2 baskets, 6 objects; from each of 2 random usable groups draw 4 cards: 1 example (already in the basket) + 3 objects. Usable group = at least 4 active cards with different words (`trim().toLowerCase()`); cards without a group are ignored; fewer than 2 usable groups shows the friendly picture screen.
- Group key = `category` trimmed and lowercased, 1-40 characters, optional. Group names are never shown to the child.
- Input: mouse only (Pointer Events); a press without movement is a tap (says the word, object stays); only Esc is a key (goes to `/games`).
- Sounds and feedback: `chime` on a right drop, then the word once; `ohOh` + the Quiz "Oh-oh… try again!" popup (1.4 s, non-blocking) + slide back on a wrong drop; a drop outside both baskets slides back silently and is not counted. Word voice: `sayWord`. Nothing plays before "tap to enter".
- Finish: `CelebrationScene`, same praise sound as Memory/Listen, "Wrong N times" (N highlighted, may be 0), buttons Play again and Back to games; nothing stored.
- Game list card colors: border `#EAD9A0`, title and icon ring `#A8842F`, icon circle `#FBF3D9` (confirmed by the PO from screenshots at the end); registry order quiz, memory, listen, sort, spot.
- Name "Sort It" (English). No hard-coded child text besides the title and the Quiz-style popup text. No timers or penalties. Honor `prefers-reduced-motion` (no lift, slide or bounce). Visible focus ring.
- Admin: Group field optional, input `maxLength` 40, saved trimmed and lowercased, blank saves as null; import key `group` (optional string, 1-40 after trim; anything else is an error with the card number, nothing imported on any error).
- Schema changes only through the new file `supabase/migrations/20261030100000_memory_cards_category.sql`. Never the service role key in the frontend.
- Checks before every commit: `npm run typecheck`, `npm run lint`, `npm test`; `npm run build` at the end of each task that adds or changes a page.
- **Branches.** Integration branch: `claude/phase2/sort-it` (cut from `develop`, already holds the spec and this plan). Each task works on `claude/phase2/st-t<N>-<topic>` cut from it and goes in by a PR into it; Claude may merge those PRs itself once the gate is green. Nothing is pushed to `develop` or `main`; the PO decides after playing it. **The migration is applied to the real Supabase project only with the PO's OK, and before anything that reads `category` is deployed** (Task 11).
- **Gate before every merge into the integration branch:** `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run e2e` (set `PW_CHROMIUM_PATH`; no stray servers on ports 3100 and 54391) all pass, and a fresh reviewer has checked the task against its spec lines. The controller takes 1920x1080 screenshots of every new screen and checks them.
- **E2E rules:** specs live in `e2e/`, run against `next start` and the stand-in Supabase, start from `reset(...)` (`e2e/support/fixtures.ts`), and fail on console errors. Dragging uses `page.mouse` (move, down, move in steps, up). No sleeps: use expect polling and the data hooks below.

## Review Focus
- The migration is not yet applied where the code runs (preview or production share one Supabase project): the game must show the friendly screen when the fetch fails, Memory Match and Listen & Pick must be untouched (their queries do not select `category`), and the release step must apply the migration first.
- The stage is scaled (window not 1920 wide): the dragged object must follow the pointer and the drop test must hit the right basket at a smaller window (test the helpers with scale 0.5 and one e2e at 1280x720).
- Pointer lifecycle: `pointercancel`, release outside the window, a second pointer or button, a press during a slide-back or settle, unmount in the middle of a drag (no listeners, timers or speech left).
- Groups written differently ("Animals", " animals "), groups with 3 cards or with duplicate words, inactive cards, blank or null `category`: one group per key, only the usable ones are drawn, nothing breaks.
- Admin and import: " Animals " saves as `animals`, blank saves as null, 41 characters are refused, `group: 5` in the import file gives an error with the card number, a blank `group` or none at all means no group, and an import card without `group` keeps working (Task 10).

### Task 6: Pointer drag hook (S3, S9)

**Files:**
- Create: `components/sort/useSortDrag.ts`
- Test: `tests/useSortDrag.test.tsx`

**Interfaces:**
- Consumes: `stageScale`, `dragDelta`, `hitBasket`, `moved`, `Pt` (Task 3).
- Produces: `useSortDrag(opts: { stageRef: React.RefObject<HTMLElement | null>; basketRefs: React.RefObject<(HTMLElement | null)[]>; busy: boolean; onPickUp: (id: string) => void; onTap: (id: string) => void; onDrop: (id: string, basket: 0 | 1 | null) => void }): { dragging: { id: string; dx: number; dy: number } | null; press: (id: string, e: React.PointerEvent<HTMLElement>) => void; cancel: () => void }`. `dx`/`dy` are in stage pixels. `press` starts a drag only for the primary button of the first pointer and only when `busy` is false; it calls `onPickUp(id)` immediately, captures the pointer on the event target, and listens on `window` for `pointermove`, `pointerup`, `pointercancel`. On `pointerup`: if the pointer never moved beyond the slop it calls `onTap(id)` (no `onDrop`); otherwise `onDrop(id, hitBasket(client point, basket rects))`. On `pointercancel` it calls `onDrop(id, null)`. `cancel()` and unmount remove the listeners and clear `dragging` without calling `onDrop`.
