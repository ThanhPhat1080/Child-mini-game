# Sort It Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the game "Sort It": the child drags 6 everyday objects into the 2 baskets they belong to (each basket starts with an example card of its group), plus admin-managed group tags (create the tags once, give each card one tag) in the admin and the JSON import.

**Architecture:** Plain React + CSS with Pointer Events written in the repo (no drag library). Pure units hold the logic (`lib/sort/groups.ts`, `rounds.ts`, `drag.ts`); a hook owns the pointer lifecycle; the page orchestrates sounds, timing and the finish. One additive migration adds the admin-only table `card_groups` and `memory_cards.group_id`; the game reads `group_id` with its own fetch so Memory Match and Listen & Pick keep their queries.

**Tech Stack:** Next.js 16, React 19, TypeScript, Supabase, Vitest + Testing Library (jsdom), Playwright (real mouse, stand-in Supabase). No Phaser (ADR-030).

**Spec:** `docs/superpowers/specs/2026-10-30-sort-it-design.md`

## Global Constraints
- Round: 2 baskets, 6 objects; from each of 2 random usable groups draw 4 cards: 1 example (already in the basket) + 3 objects. Usable group = a `group_id` with at least 4 active cards with different words (`trim().toLowerCase()`); cards without a group are ignored; fewer than 2 usable groups shows the friendly picture screen.
- A group is a row of `card_groups` (name 1-40 characters after trim, unique ignoring case); a card has at most one (`memory_cards.group_id`). Group names are never shown to the child and anon cannot read the table.
- Input: mouse only (Pointer Events); a press without movement is a tap (says the word, object stays); only Esc is a key (goes to `/games`).
- Sounds and feedback: `chime` on a right drop, then the word once; `ohOh` + the Quiz "Oh-oh… try again!" popup (1.4 s, non-blocking) + slide back on a wrong drop; a drop outside both baskets slides back silently and is not counted. Word voice: `sayWord`. Nothing plays before "tap to enter".
- Finish: `CelebrationScene`, same praise sound as Memory/Listen, "Wrong N times" (N highlighted, may be 0), buttons Play again and Back to games; nothing stored.
- Game list card colors: border `#EAD9A0`, title and icon ring `#A8842F`, icon circle `#FBF3D9` (confirmed by the PO from screenshots at the end); registry order quiz, memory, listen, sort, spot.
- Name "Sort It" (English). No hard-coded child text besides the title and the Quiz-style popup text. No timers or penalties. Honor `prefers-reduced-motion` (no lift, slide or bounce). Visible focus ring.
- Admin: groups are created, renamed and deleted in a "Groups" area (names trimmed, 1-40 characters, unique ignoring case, delete with a confirmation); a card picks one group or "No group" (no free typing); group and card edits are unsaved until Save (groups are written first), Revert discards both. Import key `group`: optional string; blank or missing means no group; a name must match an existing group ignoring case and spaces, otherwise an error with the card number; nothing is created or imported on any error.
- Schema changes only through the new file `supabase/migrations/20261030110000_card_groups.sql`. Never the service role key in the frontend.
- Checks before every commit: `npm run typecheck`, `npm run lint`, `npm test`; `npm run build` at the end of each task that adds or changes a page.
- **Branches.** Integration branch: `claude/phase2/sort-it` (cut from `develop`, already holds the spec and this plan). Each task works on `claude/phase2/st-t<N>-<topic>` cut from it and goes in by a PR into it; Claude may merge those PRs itself once the gate is green. Nothing is pushed to `develop` or `main`; the PO decides after playing it. **The migration is applied to the real Supabase project only with the PO's OK, and before anything that reads `card_groups` or `group_id` is deployed** (Task 12).
- **Gate before every merge into the integration branch:** `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run e2e` (set `PW_CHROMIUM_PATH`; no stray servers on ports 3100 and 54391) all pass, and a fresh reviewer has checked the task against its spec lines. The controller takes 1920x1080 screenshots of every new screen and checks them.
- **E2E rules:** specs live in `e2e/`, run against `next start` and the stand-in Supabase, start from `reset(...)` (`e2e/support/fixtures.ts`), and fail on console errors. Dragging uses `page.mouse` (move, down, move in steps, up). No sleeps: use expect polling and the data hooks below.

## Review Focus
- The migration is not yet applied where the code runs (preview or production share one Supabase project): the game must show the friendly screen when its fetch fails, Memory Match and Listen & Pick must be untouched (their queries do not select `group_id`), and the release step must apply the migration first (the admin page needs it).
- The stage is scaled (window not 1920 wide): the dragged object must follow the pointer and the drop test must hit the right basket at a smaller window (test the helpers with scale 0.5 and one e2e at 1280x720).
- Pointer lifecycle: `pointercancel`, release outside the window, a second pointer or button, a press during a slide-back or settle, unmount in the middle of a drag (no listeners, timers or speech left).
- Groups with 3 cards or with duplicate words, inactive cards, null `group_id`, a card pointing to a deleted group: only usable groups are drawn, nothing breaks.
- Admin: duplicate group names ignoring case and spaces ("Animals" vs " animals "), empty and 41-character names, deleting a group that cards use (their draft cards become "No group", Save order groups before cards), renaming, Revert after group edits; import with an unknown group name, a differently cased known name, `group: 5`, blank or no `group` (Tasks 9-11).
