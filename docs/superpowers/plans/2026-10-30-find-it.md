# Find It Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the game "Find It": one big picture per level, the app says and shows one object's word at a time, the child clicks that object in the picture, in the admin's numbered order, until the level is done.

**Architecture:** New table `find_levels` (one row per picture, ordered `objects` jsonb) mirroring `spot_levels`. Pure logic in `lib/find/*`, child UI in `app/games/find/*` + `components/find/*`, admin as one page `/admin/find` of level panels (same pattern as `/admin/spot`, not a per-id route). Pictures and sounds can be reused from the `media` bucket, so `removeMedia` gets a reference guard.

**Tech Stack:** Next.js 16, React 19, TypeScript, Supabase, Vitest (jsdom), Playwright with the stand-in Supabase.

**Spec:** `docs/superpowers/specs/2026-10-30-find-it-design.md` (IDs F1-F10, A20-A23). Branch `claude/phase2/find-it`.

## Global Constraints
- Child cannot read: nothing depends on text; the object word is typed by the admin; no hard-coded child-facing text. Calm & Slow: no timers shown, no penalties, no error sound, honor `prefers-reduced-motion` (`hm-reduced` class + `reducedMotion()` as in `app/games/spot/[levelId]/page.tsx`).
- Counts: 2-12 objects per level; word 1-40 chars after trim; radius `r` in 0.03-0.15 (default 0.06); hit radius `max(r, 0.04)` of picture width; small warning below 0.04.
- Timings: PROMPT_DELAY_MS 600, ADVANCE_MS 1000, FINISH_DELAY_MS 1000, RING_MS 600, RIPPLE_MS 800 (constants at the top of the play page).
- Colors: card border `#F2C9A8`, title and icon ring `#B5703A`, icon circle `#FCEFE2`.
- Child pages are read-only and unauthenticated; writes need the admin (RLS). No service role key in the frontend. Desktop Chromium only.
- Schema only through a new `supabase/migrations/*.sql`; it is applied to the real project only after the PO's OK. Never push to `main`/`develop`.
- Seed paths (`seed/…`), external links and `pending:` tokens are never deleted from the bucket (`isBucketPath`).
- Commits cite spec IDs and end with the attribution lines from the session reminder.
- Gate before every merge: `npm run typecheck && npm run lint && npm test && npm run e2e` (on the cloud image set `PW_CHROMIUM_PATH`; kill a stale `next-server` by PID, never `pkill -f`).

## Review Focus
- A level row with 1 object, an object with a blank word, or a non-array `objects` reaches the child reader: it is skipped in the grid and shows the friendly screen on direct URL, never a crash (FI-T3, FI-T6).
- The same picture is used by two levels (or by a card), one is deleted: the file must stay and still load (FI-T7, FI-T11).
- The reference check itself fails (network): files are kept, the save does not fail (FI-T7).
- Two objects overlap: a tap that is inside the other object's circle but outside the current one is a wrong tap, a tap inside the current one counts even if it also lies inside another (FI-T1).
- Window resize and tall/wide pictures keep tap mapping correct (FI-T6).
- Deleting or moving an object in the editor never leaves a word or sound on the wrong circle (FI-T9).
